# Plan: Supabase-free Gemini Vision for Prescription Scanner

## Context
The `prescription-scanner` app currently routes prescription vision through a Supabase Edge Function (`process-prescription`) that calls Gemini. Two blocking bugs (non-existent model `gemini-3.6-flash` → 404, and a wrong Gemini schema dialect) plus general Supabase setup friction meant vision never worked.

You chose:
- **Direct Gemini** vision (no Supabase Edge Function for AI).
- **Whole flow Supabase-free** for upload/processing/result (Supabase stays ONLY for auth/login).
- **Firebase added** so we can reuse the `admin_api_key_manager` package (Firestore-backed Gemini key pool) — key management only, not prescription data.
- **Result stored in local Hive** (no Firestore writes for extracted data).

## Goal
Make the camera → Gemini vision → structured result → result screen path work without Supabase, using the new `admin_api_key_manager` package for keys and a local Hive store for results.

## Approach

### 1. Dependencies & init (apps/mobile)
- `pubspec.yaml`: add `admin_api_key_manager` (git dep → `github.com/Keshab1997/admin_api_key_manager`), `firebase_core`, `cloud_firestore`, `hive_flutter`.
- `lib/main.dart`: after `WidgetsFlutterBinding.ensureInitialized()`:
  - If `AppConfig.hasSupabaseConfig` → keep `Supabase.initialize` (auth only).
  - Add `await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform)` (add `firebase_options.dart` via `flutterfire configure`, or a minimal hardcoded options file for now).
  - `await HiveFlutter.init()` + `await KeyCache.init()`.
  - `ApiKeyManager.instance.initialize()`.
- `lib/config.dart`: add `GEMINI_API_KEY` (optional dart-define fallback) so the package's `admin_api_key_keys` collection can be seeded; document in README.

### 2. New: GeminiVisionService (`lib/services/gemini_vision_service.dart`)
- Uses `ApiKeyManager.instance.getNextKey()` (provider = `google`) → `key.key` as the Gemini API key.
- Reads local compressed JPEG bytes (`File(path).readAsBytes()`), base64-encode.
- POSTs to `https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` with:
  - `systemInstruction` (constrained medical transcription rules — ported from the Edge Function's `SYSTEM_INSTRUCTION`).
  - `contents[0].parts`: `inlineData` (base64 image) + a text prompt.
  - `generationConfig`: `temperature:0`, `maxOutputTokens:4096`, `responseMimeType: application/json` (Gemini-native structured JSON — schema-free to avoid the dialect bug).
- Parses JSON → returns a `VisionResult`. On failure calls `ApiKeyManager.instance.reportFailure(...)` and retries next key; on success `reportSuccess`.
- Model: use a real model (`gemini-2.5-flash` default), configurable.

### 3. New: local result model + Hive store
- `lib/models/extracted_prescription.dart`: `ExtractedPrescription` (id, overallConfidence, needsManualReview, isPrescription, medicines: List<Medicine>, warnings, tests, followUp, createdAt) + `Medicine` (name, normalizedName, strength, dosage, frequency, route, duration, instructions, confidence, needsReview) — mirrors existing `PrescriptionDetail`/`MedicineItem` fields so UI reuse is easy.
- `lib/services/result_store.dart`: Hive-backed store keyed by prescription id (in-memory map + `Hive.box('rx_results')`). Methods: `save(ExtractedPrescription)`, `get(id)`, `getAll()`, `delete(id)`. Generates a local uuid id when the scan starts.

### 4. Wire into scan flow (`lib/screens/scan_screens.dart`)
- `UploadScreen`: after picking/preparing (`draft` has local `path`), instead of `service.reserveAndUpload` → call `GeminiVisionService.processLocalImage(draft.path)` → get `ExtractedPrescription` → `resultStore.save(...)`. Generate a local id, pass it via `context.push('/processing?prescriptionId=$id')`.
- `ProcessingScreen`: replace `service.process(prescriptionId)` with a short wait / the already-completed vision result (or just navigate straight to `/result` since vision already ran). Keep the UI spinner for UX.
- `ResultScreen`: stop using `prescriptionDetailProvider` (Supabase). Instead watch a new `localResultProvider(id)` that reads from `resultStore`. Render the same `ExtractedPrescription` (reuse existing UI widgets `_QualityHeader`, medicine list, etc. by adapting them to the new model).

### 5. Keep Supabase auth intact
- `lib/router.dart` redirect logic, `auth_service`, `auth_session_notifier` unchanged (auth stays Supabase).
- `prescription_repository.dart` (Supabase) remains for any auth-gated features but is no longer the result source for the scan flow. History screen switches to `resultStore.getAll()`.

### 6. Cleanup / safety
- Remove the now-unused Supabase upload/processing calls from the scan path (keep `prescription_upload_service.dart` file but stop invoking it in the vision flow, or delete the invoke lines).
- Update `README.md` + a short `docs/vision_setup.md`: how to seed the `admin_api_keys` Firestore collection with a Gemini key (provider=`google`, baseUrl=`https://generativelanguage.googleapis.com`, model=`gemini-2.5-flash`), and the `GEMINI_API_KEY` dart-define fallback.
- Keep the security rule: no Gemini key in Flutter source (it lives in Firestore via the package, fetched at runtime).
